# 팀 비전 + 출석 핵심가치 기능 설계

작성일: 2026-07-01
대상 프로젝트: gesi ERP (Next.js + Supabase)

## 개요

기존 사내 ERP에 두 가지 기능을 추가한다.

1. **팀 비전 페이지** — 직원이 자기 팀(커머스팀/콘텐츠팀)의 비전·핵심가치·분기목표·조직도를 ERP 안에서 본다. 팀별로 자기 팀 것만 보인다.
2. **출석 핵심가치 팝업** — 출근 체크인 시 "오늘의 핵심가치"(DO 1개 + DON'T 1개)가 팝업으로 뜨고, 출근할 때마다 다음 것으로 순환한다.

---

## 기능 1 — 팀 비전 페이지

### 목적
- 직원이 "우리 팀이 어디로 가는지 / 이번 분기에 뭘 하는지 / 어떤 가치로 일하는지"를 항상 볼 수 있게 한다.
- 개인 KPI·성과급·연봉 등 민감 정보는 제외한 **공유용** 버전만 노출한다.

### 팀 구분 (기존 기능 재활용 — 신규 개발 최소)
- `profiles.team` 컬럼이 **이미 존재**한다. 값: `'커머스팀'` | `'콘텐츠팀'` | `null`(미지정).
- 직원별 팀 지정도 **이미 완료**되어 있다.
- `app/(main)/kpi/page.tsx`에 있는 **effectiveTeam 패턴**을 그대로 재사용한다:
  - 일반 직원 → 본인 `profiles.team`의 비전만 표시
  - 관리자(`role === 'admin'`) → 커머스팀/콘텐츠팀 전환 토글로 둘 다 열람

### UI / 라우팅
- `components/Sidebar.tsx` 왼쪽 메뉴에 **`우리 팀 비전`** 항목 추가.
- 새 라우트 `app/(main)/team-vision/page.tsx` 생성.
- 로그인한 직원의 팀에 따라 해당 팀 비전 콘텐츠를 렌더링. 관리자는 상단 토글로 팀 전환.
- `team`이 `null`(미지정)인 직원은 "관리자에게 팀 지정을 요청하세요" 안내 표시.

### 콘텐츠 (공유용 — 민감정보 제외)

기존 관리자용 OS HTML(`kirin-os.html`, `content-team-os.html`)을 원본으로 하되, 아래를 **제외**한다:

**❌ 제외 (직원에게 안 보임)**
- 직원별 핵심숫자 / KPI 3축
- 기본급 / 성과급 / 복리후생 / 서명란
- 인사 변동 박스 (연봉 인상, 신혼여행 등 개인 사정)
- 개인 열정지점 / 성과급 트리거

**✅ 포함 (팀 공유)**
- 미션 (팀이 가는 방향)
- 5년 비전 / 목표
- 핵심가치 (전문성·대중성·역동성 + 각 DO/DON'T)
- 분기 짱돌 (팀 공동 목표)
- 책임조직도 (자리 + 담당자 이름 — 숫자·성과급 없이)

### 표시 방식
- 공유용 콘텐츠를 **React 컴포넌트**로 작성한다 (ERP의 기존 스타일/레이아웃과 통일, 유지보수 용이).
- 커머스팀용 컴포넌트 1개 + 콘텐츠팀용 컴포넌트 1개.
- (대안: 공유용 HTML을 `public/`에 정적 파일로 두고 iframe 임베드 — 더 빠르지만 스타일이 ERP와 이질적. 기본은 컴포넌트 방식.)

## 기능 2 — 출석 핵심가치 팝업

### 목적
- 매 출근 시 핵심가치를 1개씩 각인시킨다. 출근할 때마다 다음 것으로 순차 순환.

### 핵심가치 데이터 (9쌍 순환)

| # | 가치 | DO ✅ | DON'T ❌ |
|---|------|-------|----------|
| 1 | 전문성 | 기획 먼저 (의도·예상결과 정하고 시작) | 같은 실수 반복 (같은 피드백 2회+) |
| 2 | 전문성 | 내 결과물은 내 얼굴 (검수 전 셀프 완벽검증) | 과정 호소 ("밤샜는데…") |
| 3 | 전문성 | 시간은 신뢰 (못 지킬 것 같으면 미리 공유) | 문제 은폐 (혼자 끙끙) |
| 4 | 대중성 | 고객 집착 (리뷰·CS·CTR이 최고 근거) | 공급자 마인드 ("내 감엔 멋있다") |
| 5 | 대중성 | 눈높이 번역 (중학생도 이해) | 고객 무시 (진상 취급) |
| 6 | 대중성 | 선제적 제안 ("이거 필요하시죠?") | 시장성 무시 (안 팔리는 예술) |
| 7 | 역동성 | R&R 초월 ("제가 해보겠습니다") | 수동적 태도 (시키는 일만) |
| 8 | 역동성 | Solution 지향 (해결책까지 들고 보고) | 핑계 ("지시 없어서") |
| 9 | 역동성 | Agile & Trend (80점이라도 오늘 출시 / 밈을 내일 콘텐츠에) | 굼뜬 태도 (원래 계획만 고집) |

- 데이터는 코드 내 상수 배열로 관리 (초기 버전). 나중에 편집 화면은 별도.

### 순번 결정 (어떤 걸 보여줄지) — 확정: 날짜 기반 전사 공통(B)
- **전 직원이 같은 날 같은 가치를 본다.** 고정 시작일(`2026-07-01`)부터 오늘까지의 **평일 수**를 세어 `평일수 % 9`번째 가치를 그날의 가치로 정한다.
- 주말·공휴일은 건너뛴다(평일만 카운트). 개인별 출근 횟수와 무관하게 그날의 가치가 정해지고, 출근한 직원에게 그날의 가치를 팝업으로 보여준다.
- 장점: 개인별 출근 횟수 집계 불필요(오늘 날짜만으로 계산), "오늘 회사 전체가 같은 가치"로 각인.
- 공휴일 데이터가 없으면 1차 버전은 **주말만 제외**하고 진행(공휴일 반영은 후순위).

### UI / 붙일 지점
- `app/(main)/attendance/page.tsx`의 `handleAction('check_in')`가 **성공한 직후** 모달을 띄운다.
- 모달 내용: 가치명(전문성/대중성/역동성) + DO + DON'T + "확인" 버튼.
- 퇴근(`check_out`)에는 뜨지 않는다. 출근에만.
- 하루 1회 출근이므로 하루 1회만 뜬다.

## 범위 밖 (YAGNI — 지금은 안 만듦)
- 핵심가치/비전 내용을 화면에서 편집하는 관리자 UI (초기엔 코드로 관리)
- 출석 핵심가치 노출 이력·통계
- 팀 3개 이상 확장 (현재 2팀 고정)

## 확정된 결정
1. 핵심가치 순번: **날짜 기반 전사 공통(B)** — 전 직원이 같은 날 같은 가치 (평일 수 % 9)
2. 비전 표시: **React 컴포넌트** — ERP 스타일 통일

## 작업 순서
1. 공유용 팀 비전 콘텐츠(커머스/콘텐츠) 2개 작성 — 민감정보 제외
2. 왼쪽 메뉴 + `/team-vision` 페이지 (팀 인식 = 기존 effectiveTeam 재활용)
3. 출석 체크인 성공 시 핵심가치 모달
